## Traceability rules

- **Founder intent** is recorded in #170; prior documents are only superseded after an accepted ADR/change-approval path. Do not rewrite historic four-page behavior without versioning/migration.
- **Accepted ADR** is the contract. A node referring to ADR 0013 does not make a new 6/8/12-page format already supported. [#44](https://github.com/interzettel/kushluk/issues/44) owns actual duplicate ADR 0012 resolution.
- **Feature catalogue** [#87](https://github.com/interzettel/kushluk/issues/87) and [FEATURE_CATALOG.md](../FEATURE_CATALOG.md) own shipping/target statuses. Mapping an F-ID to a strategy branch is not moving it into beta.
- **Task authority** [WORK_LEDGER.md](../WORK_LEDGER.md) retains **90 original IDs**. Some are checked as historical narrow slices. A new scope may need a *new* task ID after founder acceptance, but no old checked task becomes undone or a new one marked complete from this atlas.
- **Gates** [PROGRESS.md](../PROGRESS.md) remain independently verified **0/8** as of the recorded baseline. These rows merely indicate which gates may need stronger evidence or updated wording if a new contract is accepted.
- **Cross-issue reviews** take place on discussion rooms [#158–#162](https://github.com/interzettel/kushluk/issues/158) and [#171–#176](https://github.com/interzettel/kushluk/issues/171); all-issue master catalogue #43 must be reconciled when new issues are opened.
- **No automatic syncing** of issue comments or Project fields is claimed. The JSON/HTML/Markdown are versioned **snapshots**. A lightweight refresh tool updates HTML from JSON, and CI checks their exact equality; a future GitHub Project status adapter would require permissions and separate testing.
